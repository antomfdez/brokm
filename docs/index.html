Hello, brokm

// hello.bk — top-level code runs; a bare string statement prints.
"Hello World\n";

I64 Fib(I64 n)
{
  if (n < 2) return n;
  return Fib(n - 1) + Fib(n - 2);
}

I64 i = 0;
for (i = 0; i <= 10; ++i)
  "Fib(%d) = %d\n", i, Fib(i);

Type-first declarations, top-level code (no main()), and HolyC-style "..."; printf-printing. Hot functions like Fib are compiled to native arm64/x86-64 code at runtime.

What's inside

Bytecode VM

A compact stack VM: lexer → parser/AST → bytecode compiler → interpreter.

Generational GC

Precise, non-moving mark-sweep with minor/major collections and a load-bearing write barrier.

Aggregates

Dynamic arrays and reference-semantics classes/structs with typed fields.

Manual memory

Opt-in MAlloc/Free with typed peek/poke for low-level work — GC-invisible.

Static type checker

Validates HolyC type annotations before execution; gradual, so existing code is unaffected.

Baseline JIT

Profile-gated arm64 + x86-64 code generation for hot functions, ~2× faster on recursion, with a full interpreter fallback.

Standard library

File I/O, string ops, and math builtins — enough to write a brokm tokenizer in brokm.

Get started

Requires a C99 compiler and make — no external dependencies.

  1. git clone https://github.com/antomfdez/brokm
  2. cd brokm && make  builds ./brokm (0 warnings)
  3. ./brokm file.bk  run a program — or ./brokm for the REPL
make           # build ./brokm
make test      # run the golden test suite
make test-gc   # run it with the GC firing on every allocation
make bench     # benchmark the JIT against the interpreter

Embedding

#include "brokm.h"

int main(void) {
  brokm_init();
  brokm_eval("\"embedded!\\n\";");
  brokm_shutdown();
  return 0;
}
